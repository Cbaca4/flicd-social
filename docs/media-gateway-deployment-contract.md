# Media gateway deployment contract — NOT deployment approval

## Supported topology and present limits

The repository contains a dependency-injected library, not an Internet listener or a production composition. Its only current compositions are loopback synthetic test fixtures. It MUST NOT be exposed directly to the Internet. Deploy only behind separately implemented, reviewed ingress AND controlled upstream egress; prevent all bypass access to the private process/container (loopback/unix socket or authenticated private network). `allowedOrigins` is CORS validation, NOT an authentication/rate-limit/network firewall.

Review references:

- `server/media/gateway.mjs:31-32`: Request.text() buffers before the 8192-byte check. It does not bound allocation for oversized/chunked/slow bodies.
- `server/media/gateway.mjs:41-44`: byte/type and source rechecks occur after adapter download. They preserve authorization but do not impose transport deadlines or process concurrency.
- `server/media/supabaseAdapter.mjs:21-23`: SDK download materializes a Blob before size/arrayBuffer checks. A post-download 20 MiB check does not cap upstream allocation, redirects or elapsed time.
- Neither module implements distributed rate limiting or total-request deadlines. There is no production hosting file implementing these controls here. No production-readiness claim is made.

## Required enforceable controls before any hosted activation

The following concrete initial operational envelope must be implemented, capacity-tested and independently approved in the actual composition. These are deployment requirements, not newly applied product posting/storage limits.

1. TLS at the edge; exact host/route/method allowlists for POST/OPTIONS only. Reject query-string capabilities, conflicting Content-Length/Transfer-Encoding and unsupported encodings. Do not accept compressed request bodies. Limit total headers to 16 KiB and individual Authorization to 8 KiB; redact it from every access/error/trace log. Configure trusted proxy hops explicitly; clients cannot choose their limiting IP via forged forwarding headers.
2. Enforce 8192 decoded JSON body bytes BEFORE forwarding/buffering into Request.text(), including chunked/no-Content-Length traffic. Reject oversized declared bodies immediately and stop/cancel the stream on byte 8193. Do not spool unbounded bodies or drain infinite input after rejection. Limit request header time to 5 s, body time to 10 s and idle body gaps to 3 s. Return 413/408 without invoking private media authority after transport rejection.
3. A total media request budget of 30 s includes Auth, RPC, download, final authorization and response. Auth/RPC calls must each have a 5 s deadline and a 3 s connection timeout; reserve at least 5 s for the final authorization check. Client disconnect or deadline must actually abort upstream work or terminate a request-isolated worker, not merely abandon a Promise or close the public connection. A reverse-proxy timeout alone is insufficient.
4. Restrict upstream destinations to explicitly approved Supabase Auth/RPC/Storage origins and exact operation families; no user-selected URLs, redirects or DNS rebinding/SSRF paths. Enforce upstream download length at the streaming egress boundary before the SDK Blob: maximum 20 MiB, even with missing/false Content-Length, chunked encoding or decoded content expansion. Stop at byte 20971521 and abort/cancel. Only JPEG/PNG/WebP are gateway outputs. Do not stream any bytes to the browser before final SQL authorization/location recheck succeeds.
5. Enforce concurrent buffered frame downloads: at most 2 per authenticated account and 4 per instance initially. Provide a bounded queue (at most 8 entries/instance, at most 2 s waiting); reject excess with 429/503 and release permits on every completion, abort and failure. Size the memory limit using measured simultaneous SDK Blob/ArrayBuffer/Response copies at 20 MiB each, not only one buffer. Do not approve capacity without load/slow-client/slow-upstream tests and a hard resource limit.
6. Use distributed, fail-closed rate limiting across all instances. Initial limits: unauthenticated/Auth-attempt traffic 10 requests/minute/IP, burst 5; authenticated control/metadata traffic 60/minute/account, burst 10; frame delivery 120/minute/account, burst 20; new View Once claims 5/minute/account, burst 2. Associate authenticated limits with verified account/session identity, not a body/JWT field decoded without server validation. Explicitly test that retries do not refund claims or permit a limiter bypass. Revisit this reviewed operational envelope against actual navigation/collection demand before rollout; never bypass the durable per-account SQL consumption rule.
7. Private no-store response headers must survive proxies/CDNs for successes AND errors. Do not publicly cache, sign or publish private byte paths/capabilities. Keep service credentials backend-only; browser identity derives from server-validated Auth. Retain final source/session/block/lease rechecks and source-location equality before emitting buffered bytes.
8. Cleanup workers are private/operator managed, concurrency bounded, retries/backoff monitored and leases/retention authorization checked immediately before deletion. Drain every old worker before migrating or activating the new version. Do not run real cleanup or provenance adjudication merely to validate deployment.

## Required hostile-transport evidence

Before lifting the activation gate, demonstrate real ingress/egress tests for: oversized declared/chunked bodies; body/header trickling; malformed/ambiguous framing; never-ending/cancelled streams; wrong/missing content lengths; >20 MiB upstream data; stalled Auth/RPC/download; client disconnect; permit exhaustion/release; distributed limiter/forwarded-IP bypass attempts; byte-integrity and no-store preservation; source deletion/block/session expiry during download. Observe both memory and outstanding sockets/work after timeout. Test real provider SDK behavior with separately approved synthetic accounts, not production data.

If a future composition is directly Internet-facing or any ingress/egress boundary above can be bypassed, documentation is NOT sufficient: implement and test streaming byte counters, actual cancellation/deadlines, concurrency and distributed limiter enforcement before publication as an Internet-ready service. This round does not implement that composition, activate a service or approve deployment. The current buffered library may be reviewed on GitHub only with this explicit deployment limitation retained.
